# Current handover — AFK FARM 0.7.0 UI

The engine side of 0.7.0 is done and tested; the panel still shows the 0.6.5 pages
(one line changed: `/api/state?slot=<selected>`). The new features need their UI.
Read AGENTS.md, README.md, docs/UI_CONTRACT.md (section "0.7.0: hero roster,
collection, Siege and workers") and the module notes of tools/siege.py and
tools/workers.py first. Use the isolated fixture: `py -3 -B tests/serve_panel_fixture.py`
(port 9567; two heroes on the roster, a Siege, a delivered claim with uniques, a
wishlist item, a Siege record, a special monster, two workers; hiring and
collecting are simulated). Never run tools/panel.py against real data for UI work.

## What to build (English UI only, no new dependencies, no API changes)

1. **Roster on Explore.** A strip or list of `expeditions[]`: hero, region, mode
   badge (Expedition / Siege), countdown to `ready_at`, delivery progress, ready
   state. Selecting a row selects that hero (the page already sends `slot`). A hero
   with an active expedition shows it; a free hero shows the planner. Several heroes
   can run at once; delivery stays one at a time with the hero loaded in the game.
2. **Siege in the planner.** A mode switch (Expedition / Siege), a level picker
   1-50 with the forecast from `/api/siege-forecast` (median waves and 10-90% range,
   fall chance, Magic Find bonus, suggested level, the hero's best at that level),
   then `start` with `mode: "siege", siege_level`. While it runs: current wave, gate
   bar (`hp`/`gate_hp`), the last waves (held or damaged), the next special wave,
   and "Report ready" when `over`. Never reveal future waves. Records table from
   `siege_records`. Say plainly that Siege is a challenge layer over the measured
   pace and that every item is still generated by the game.
3. **Collection.** A new page (or a Loot tab): totals by rarity, sets with their
   pieces, search, found/missing filter, first-found details, and a wishlist star
   per item (`wishlist_add` / `wishlist_remove`). On rewards, badges for
   `wishlist_hits` and `new_finds`.
4. **Share.** A "Share card" button on each delivered reward that calls
   `AfkShare.download(reward.id)` (web/share.js, already loaded).
5. **Workers.** A new page: crew cards (name, level, XP bar, points, trip
   countdown), Hire with `hire_price` (explain: it takes that much gold from the hero
   loaded in the game; the game must be open with an offline hero), the skill tree
   (5 branches, ranks, prerequisites, Learn, Reset skills with `respec_price`), the
   trip planner (ore picker with locked ores and their levels, hours up to
   `max_trip_hours`, the real duration from `time_factor`), Collect (game open with
   any offline hero; also happens after every claim), history and stats, Transfer
   to Vault for a waiting haul, Close as partial for a stopped haul. Show `job.error`
   texts as they come.
6. **Special monsters** (Settings or Calibration): `/api/specials` with a Verify
   button per monster (`verify_special`), explaining that any offline hero must stand
   in that region and that the check makes no rewards.

Keep keyboard/focus/narrow-screen behaviour of 0.6.5. Extend
tests/test_panel_ui.cjs for the new views. Report in docs/UI_REFRESH_VERIFICATION.md.
